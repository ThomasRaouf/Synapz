# Synapz

Synapz is a study app for med and engineering students. Upload your notes,
slides, PDFs, or textbook chapters, and it turns them into AI-generated
summaries, with mind maps, quizzes, and flashcards on the way. The idea is
to take the "I have 40 pages and no time" panic and turn it into something
you can actually study from in five minutes.

We're a team of three, building this in our spare time, mostly figuring
things out as we go. This README is meant to actually reflect that, not a
polished marketing page, just an honest snapshot of what's built, what's
duct-taped together, and what's still fake.

## Where things actually stand

Some of this works for real now:

- **Uploading materials** : drop in a PDF, a Word doc, or just paste notes,
  and it gets stored (file goes to Supabase Storage, the record goes to
  Postgres).
- **Text extraction** : PDFs and DOCX files get parsed into clean text
  (`services/pdf_parser.py`, `services/docx_parser.py`).
- **AI summaries** : real ones, generated by Gemini, with a defined
  structure (overview, key concepts, definitions, quick review). If nobody's
  set up an API key, it quietly falls back to a mock summary so the app
  doesn't just break in dev.

Some of it is still smoke and mirrors:

- **Flashcards, quizzes, and mind maps** are running on hardcoded demo
  content right now. They look and feel real, but they're not generated from
  whatever you actually uploaded yet, that wiring hasn't been built.
- **No login.** Everything is effectively shared/anonymous for now.
- **Images** are accepted by the uploader but nothing processes them yet.

So: closer to a real product than a skeleton, not yet the whole vision.
That's expected, we're building this one feature at a time on purpose,
instead of half-building everything at once.

## Stack

- **HTML/CSS** : plain, no frameworks. We wanted to actually understand our
  own layout code before reaching for Tailwind or Bootstrap.
- **Vanilla JavaScript** : no React, no build step. You can open the file,
  read it top to bottom, and know exactly what it does. That matters a lot
  more to us right now than saving keystrokes.
- **Python + FastAPI** : our backend. Genuinely great docs, automatic
  request validation, and a `/docs` page you get for free — good for a team
  where nobody's shipped a production API before.
- **Supabase** : Postgres database + file storage + (eventually) auth,
  without us having to run our own servers.
- **Gemini (`google-genai`)** : does the actual summarizing. Swappable later
  if we outgrow it — `services/ai_service.py` is the one place that would
  need to change.
- **Git + GitHub** : version control and where we review each other's work.
  See `CONTRIBUTING.md` for how we actually use branches and PRs.

## Project layout

```
Synapz/
├── backend/
│   ├── main.py                 # FastAPI app, wires up all the routers
│   ├── routes/                 # HTTP endpoints (materials, processing, summaries)
│   ├── services/               # actual logic: parsing, AI calls, Supabase
│   └── models/                 # pydantic schemas / request-response shapes
└── frontend/
    ├── index.html               # the whole app is one page, view-switched via JS
    ├── js/                       # one file per feature area, loaded as plain <script> tags
    └── css/
```

No bundler, no `npm install` for the frontend, no magic. What you see in the
file is what runs in the browser.

## Running it locally

### 1. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file inside `backend/` (never commit this — it's already in
`.gitignore`):

```bash
SUPABASE_URL=your-supabase-project-url
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
SUPABASE_BUCKET=study-materials      # optional, this is the default anyway
GEMINI_API_KEY=your-gemini-key       # optional — no key = mock summaries, not a crash
```

Then run it:

```bash
uvicorn main:app --reload
```

You should see it come up on `http://127.0.0.1:8000`. Hit
`http://127.0.0.1:8000/api/health` in your browser — if you get back
`{"status": "ok"}`, you're good. There's also `/docs` for a live, clickable
API explorer, which is genuinely worth poking around in.

### 2. Frontend

No build step, just open `frontend/index.html` in a browser, or serve it
with anything simple:

```bash
cd frontend
python -m http.server 5500
```

Heads up: `frontend/js/api.js` currently has the backend URL hardcoded to
`http://127.0.0.1:8000`. That's fine for local dev but it's the first thing
that'll need to change before this can talk to a deployed backend — it's on
the list, not forgotten.

### Deploying (for reference)

- The frontend auto-deploys to GitHub Pages on push to `main`
  (`.github/workflows/static.yml`).
- The backend deploys to FastAPI Cloud the same way
  (`.github/workflows/deploy.yml`), and needs `FASTAPI_CLOUD_TOKEN` and
  `FASTAPI_CLOUD_APP_ID` set as repo secrets.

## Known rough edges

Being upfront about this so nobody spends an hour thinking they broke
something:

- CORS is wide open (`allow_origins=["*"]`), that's a deliberate dev
  shortcut, not something to copy into production.
- The frontend's local material list and the backend's database can drift
  out of sync, we know, it's on the board.
- Error messages are still a mix of genuinely helpful and "please try
  again", we're improving these as we touch each route.

If you hit something weirder than this list, it's probably a real bug,
open an issue or flag it in the group chat rather than assuming it's you.

## Troubleshooting

**"Could not reach backend. Is it running?"** — the frontend can't reach
`http://127.0.0.1:8000`. Check the terminal where you ran `uvicorn`, is it
still open, and did it print an error instead of `Uvicorn running on...`?
Also double check you're not running the frontend from a different port that
your browser is blocking via CORS.

**Backend won't start / `ModuleNotFoundError`** — you probably need to
re-activate your virtual environment (`source .venv/bin/activate`) and/or
rerun `pip install -r requirements.txt`.

**AI summary comes back weirdly generic ("Mock Summary: Cellular
Respiration")** — that's not a bug, that's the fallback. It means
`GEMINI_API_KEY` isn't set in your `.env`, or the backend didn't pick it up
(restart `uvicorn` after editing `.env`).
